=== Descrição ===
Fixes #18.

### Problem
Loading any save crashed with `FATAL: no function at 8006eb850`. The `br x12` at main 0x8006eb84c is a byte jump table with 7 targets. The table register `x28` is set once (`adrp`/`add`, at 0x8006eaeb0) and reused for other values before the `br`. So:
- the emulation in `jump_table()` reads the table at the scratch address and finds a single target (0x8006eb7b0);
- `_jump_table_scan` gives up, because the closest earlier write of `x28` is not the `adrp`/`add` pair;
- `jump_table()` then returned that single unconfirmed target, so the other 6 targets were never labels.

### Change
When the scan can't confirm the table and the emulation found at most one target, `jump_table()` returns `None`. The `br` then gets the existing `computed_target` → `'all'` fallback, as any unresolved table does. 7 lines, in `tools/lifter/gen.py` only.

### Scope and testing
- On main (1.4.3) this changes 3 `br`s (`jumptables_single_unconfirmed: 3` in the lifter stats). The jump tables that already resolve are unchanged.
- Tested on Windows (RTX 4090 laptop): lift + compile, then load a save made on 1.4.3 and play. Before the change, it crashed every time while the save loaded.
- An alternative I tried and dropped: widening `_jump_table_scan` to accept any single `adrp`+`add` of the table register in the function. It fixed 0x8006eb84c, but it turned main 0x801553050 (which had `'all'`) into a 43-target table missing 0x8015485b0, and the game crashed later with `no function at 8015485b0`. The fallback here is the conservative version.
